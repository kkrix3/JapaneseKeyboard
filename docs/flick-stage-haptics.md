# フリック段階振動（実験機能）

`feature/custom-haptics` を基点とした追加機能です。初期OFFです。
「操作フィードバック」または旧設定画面の「共通」→振動設定で有効にします。
振動全体のON/OFFは既存の `vibration_preference` のみを使用します。
押下・リリース・両方・カスタムの各タイミングと共存します。

## 選択経路と振動

認識器の現在の経路を比較し、共通接頭部より後を取り消し・選び直しとして扱います。
文字プレビューの長さや内容から段数を推測しません。

| 変化 | 振動 |
|---|---|
| 中央→1段目、1段目→2段目など | 進行 |
| 2段目→1段目、1段目→中央など | 後退 |
| `[上,右]`→`[上,下]` | 方向変更（後退→進行） |
| 同じ経路 | なし |
| 離指・キャンセル | 段階振動の追加なし。未送信の予約を取消 |

中央を経由する実際の後退・進行に方向変更イベントを重ねて発火しません。
複数段を飛び越えた差分は、取り消し段数・進行段数分の再生命令を生成します。
同時命令の上書きは許容し、入力認識を待機させません。

## 対応範囲

`FlickKeyboardView` の通常フリック、十字・花びらフリック、中央ガイド、
2段フリック、Sticky 2段フリック、階層フリック、ドーナツに接続します。
特殊キーの通常フリックも対象です。特殊キーの長押し固有動作、
タップ長押し専用・フリック長押し専用の認識器、QWERTYは対象外です。
階層の上限は追加しません。サブメニューを開いた際の入口方向の重複は1段と数えます。
Sticky認識器が選択を維持する動作では、実際の経路が戻らない限り後退振動は出ません。

## 設定と波形

| 項目 | 初期値 |
|---|---|
| 段階振動 | OFF |
| オシレーション抑制 | ON |
| 抑制時間 | 40ms、0～200ms（5ms刻み） |
| 方向変更モード | ON（アプリ側の時間差） |
| アプリ側時間差 | 30ms、0～200ms（5ms刻み） |
| 進行波形 | 強度 `[50,100,50]`、各5ms |
| 後退波形 | 強度 `[50]`、5ms |
| 方向変更の独立複合波形 | 強度 `[50,0,50,100,50]`、時間 `[5,25,5,5,5]` ms |

アプリ側モードは後退命令の開始から30ms後に進行命令を送ります。
複合波形モードは独立波形を1回送ります。その間隔をアプリ側設定から自動生成しません。
OFFは後退・進行を即時に送信し、上書きを許容します。
波形3種類は既存のエディタで個別編集し、既存の確定時波形とは別に保存します。
時間値は実機調整用の仮値です。

オシレーション抑制は同じ親経路の同じ境界（方向同士・中央と方向）の
2回目以降の横断が抑制時間内に起きたときに振動だけを抑えます。
横断のたびに時刻を更新するため、連続往復中は抑制が継続します。
違う境界を進む高速の多段操作には一律の時間制限を適用しません。
抑制中も観測経路は更新し、文字入力・プレビューは従来どおりに動きます。

新しい選択経路、別キーへのDOWN、UP、CANCEL、キーボード再構築・デタッチ、
マスターOFF、段階設定・波形の変更、設定インポートは未送信の予約を取り消します。
別キーの開始後に前キーの終了通知が届いても、新しいキーの予約を取り消しません。
既にAndroidへ渡した波形（複合波形を含む）は完了を許容します。
既存のリリース振動を止めないため、`Vibrator.cancel()` は呼びません。

## 保存・互換性

全項目は既存のSharedPreferencesへ保存し、既存設定のエクスポート・インポートに含めます。
旧バックアップで項目がない場合は初期OFFと既定波形に戻ります。
進行・後退・複合波形の編集は既存の通常・2段・特殊キー波形を変更しません。
段階振動でも既存のメディア使用設定とAndroid側の触覚ON/OFFを尊重します。

## 実機確認

1. 既存振動のタイミング4種類それぞれで、段階振動OFF時の従来動作を確認。
2. 段階振動ONで、1段進む・戻る・方向変更・同じ方向保持を確認。
3. 通常、2段、Sticky、3段以上、ドーナツ、特殊キーの通常フリックを比較。
4. 抑制ON/OFF × 再生モード3種類の6条件を比較。高速操作と境界の往復を含める。
5. アプリ側時間差を長め（例200ms）にして、離指・別キー・マスターOFFで予約が消えることを確認。
6. 3種類の波形を編集・保存・再表示し、既存波形が変わらないことを確認。
7. 設定をエクスポート・インポートし、波形・モード・数値・ON/OFFの復元を確認。

必要なら `adb shell setprop log.tag.FlickStageHaptics DEBUG` を設定し、
`adb logcat -s FlickStageHaptics` で生成・抑制・再生命令・予約取消を確認します。
入力した文字列はこのログに出しません。再生命令の記録は実際の振動知覚を保証しません。
