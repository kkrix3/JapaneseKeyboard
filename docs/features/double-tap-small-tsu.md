# ダブルタップ促音入力

基点: `a47715a453cee3ecb40e9757ffbd7d4790ce7ae9` (作業開始時のfork dev = upstream/dev)。
背景: KazumaProject/JapaneseKeyboard#894。今回の合意済み実装指示を優先。

## 操作・設定

新しい設定ホーム: 設定 → 入力方式 → ダブルタップ促音。
旧設定: 「共通」タブ → キーボードの「入力方式」→ ダブルタップ促音。
同じ設定画面・保存項目を使うため、表示方式を切り替えても設定は共有される。
旧設定の検索でも「ダブルタップ促音」からこの入力方式への導線を探せる。
初期OFF、判定時間200ms (50〜500ms、1ms単位)。
行選択は2回目に実際に入力する文字列の先頭で判定し、キーのラベルや1回目の行は使わない。
既定: か・が・さ・ざ・た・だ・は・ば・ぱ。
ショートカットバーの編集から「ダブルタップ促音」を追加でき、チェック表示がON。
一般設定JSONに含まれる。旧バックアップはこの機能を既定値に戻す (部分インポートも同様)。
不正な新項目はこの機能の範囲で処理し、カスタムキーボードのJSON形式は変更しない。

1回目の通常タップを直ちに処理する。1回目UP → 2回目DOWNが判定時間以下なら、
2回目完了時に自分が追加した未確定の読みだけを「っ＋2回目の文字列」に置換する。
例: あ + たタップ + 同じキー左フリック = あっち。ば + さタップ + 同じキー「じ」 = ばっじ。
カタカナは「ッ」。2回目が「こう」なら「っこう」。1回目が複数文字でも全追加範囲を置換。
連打は か → っか → っかか → っかっか。かっか は最初のかの後で時間を超えて区切る。
除外出力の場合は普通に入力し、時間内の組の2回目を次の1回目に再利用しない。

### 時間の調整と対象判定

同じキーへのタップ → フリックで普通に「かく」と入力する操作も、時間条件を満たせば
「っく」になる。意図だけを区別することはできない。意図しない促音が多い場合は判定時間を
短くすると減らせるが、促音を出すにはより素早く2回目を開始する必要がある。
普通の2文字を入力したいときは判定時間を超えて区切るか、対象行・全体のON/OFFを調整する。
初期値は200msのままで、更新時に本人の設定（例: 調整中の100ms）を上書きしない。

先頭の「っ／ッ」「ん／ン」や、かな以外の文字を含む等の除外条件も、2回目の出力へ適用する。
1回目が「っか」で2回目が「き」なら、同じキー・時間内・安全な未確定入力等の条件を満たすと
全体は「っき」。1回目の「っ」が理由で除外されるわけではなく、1回目の追加範囲全体を置換する。
1回目が「か」、2回目が「っ」なら2回目が対象外のため「かっ」。複数文字も含めた範囲は下記参照。

## 設計と安全条件

coreのSmallTsuSessionが単調イベント時刻を受け取る。タイマー・sleep・入力の保留なし。
Viewは同一インスタンス／レイアウト世代／論理キーとDOWN/UPを通知する。
通常の出力callbackを同期的に1回だけ呼ぶため、既存のフィードバック回数を維持する。
既存明示ダブルタップ割当ては変更せず、自動促音から除外。

IMEは接続オブジェクト、セッション、読みの変更世代、入力モード、操作境界、読み全文を照合。
末尾一致だけでは置換せず、1回目が読みへ正確に追加されたことも検査する。
読みと変更世代は一組で取得する。StateFlowの並行更新・再入するcollectorでも世代を失わず、
読みが一度変わって戻った場合を同じ状態と誤認しない。共有する保護区間にIPCや待機処理は置かない。
確定、候補選択、削除、選択、入力先・View・設定変更、取消、多指、長押し等で予約を捨てる。
外部カーソル変更と自分のcomposing表示への通知は、既知の表示範囲の応答列で区別する。
不明な選択状態、未確定読みのカーソル途中、パスワード、直接入力では通常入力へ戻す。
同期の文字取得IPC、確定済み文字のBackspace/deleteSurroundingTextは追加しない。

フリックプレビューとライブ変換表示は読みと別管理。置換時に古い候補トークン・
Zenz表示・変換学習セッションを無効化し、読みの通常更新へ渡す。
ハプティクス機能は追加・移植していない。

## 範囲

TenKey (フリック専用)、Sumire (フリック専用)、共通FlickKeyboardViewによる通常・円形／
ドーナツ・2段・階層3段・カスタムかな。通常／フローティング／分割の共通bindingに接続。
トグル入力、明示ダブルタップ、長押し、直接確定／複数文字即時確定は除外。
物理・QWERTYローマ字・独立Gojuon・手書き・記号面は今回対象外。
IME内のフローティング辞書編集欄も、安全な入力先追跡の対象外として通常入力を維持する。
ひらがなU+3041〜3094、カタカナU+30A1〜30F4と長音符を対象とし、NFCは判定にだけ使う。
合成濁点／半濁点・全角の濁点表現を認識するが、出力表現は保存する。
「ゔ／ヴ」はあ行扱い。先頭ん／ン、既存促音、半角カナ、拡張かな、小書きヵヶ、
踊り字、漢字・ASCII・空白・句読点・絵文字を含む出力は対象外。

## 検証

ローカルGradleは配布ZIP取得でNetwork is unreachable。AndroidテストはGitHub CIで実行し、
実行結果を別途記録する。単体／View／実際のIME＋入力欄／実機の結果を分けて報告する。
機能ブランチは配布設定を含まない。Feature基盤と通常mergeしたverifyブランチからビルドする。

基点のonUpdateSelectionは未確定範囲があると早期returnする。このため外部アプリが
カーソルを動かしても、従来の未確定末尾へ次のかなが追記される場合がある。
今回の予約はその通知で取り消すが、既存IMEのカーソル処理は変更しない。
実IMEテストは機能OFFで同操作を測定し、ONでも既存文字と1回目を保持して同じ位置へ
通常入力することを比較する。カーソル位置の新仕様を促音テストへ紛れ込ませない。

実IMEの時間条件のある組は、公開API `WindowInspector` で起動中のIMEウィンドウを取得し、メインスレッドでルートViewへ実時刻のDOWN/UPを送る。実Service・InputConnection・入力先EditText・候補処理を通し、listenerやモックを直接呼ばない。UP→DOWN間隔と1回目が長押しになっていないことをassertし、時刻をログに残す。OSのInputDispatcher全体を通す操作とは区別する。単独入力・カーソル操作のケースでは `UiAutomation` のOS注入も残す。単体／View試験の199/200/201ms境界は維持する。

Android 15の `UiAutomation` は `sync=false` でもwindow transactionの同期を行うため、短時間操作の再現にその呼出間隔を使わない（[API文書](https://developer.android.com/reference/android/app/UiAutomation#injectInputEvent(android.view.InputEvent,%20boolean))、[プラットフォーム実装](https://github.com/aosp-mirror/platform_frameworks_base/blob/android-15.0.0_r1/core/java/android/app/UiAutomationConnection.java)）。

フローティング試験ではドックとポップアップの両方のrootが残るため、実際の表示キーを取得したアクセシビリティwindow IDと一致するrootへ送信する。座標の重なりだけで対象windowを選ばない。
入力時刻はテストスレッドで採取し、IMEメインスレッドへ順序どおりpostする。最後のUPの処理完了だけを待ち、View探索や各イベントの処理時間を押下時間へ混ぜない。
